# 标签组管理器（Tab Group Manager）

[English](README.en.md) | [中文](README.md)

<img src="icons/icon128.png" alt="扩展图标" width="96" align="right" />

Chrome MV3 扩展，把标签栏整理成“分组优先、只展开一个分组”的工作区：

- 分组标签页排在未分组标签页之前；钉住的分组按自定义顺序排在最前。
- 未分组标签页自动进入每个窗口的默认分组（默认灰色 `其他`）。
- 每个窗口同时只展开一个分组：当前标签页所在分组；当前是固定标签页时保留上次展开的分组。
- Ctrl+T / 新标签页进入当前展开的分组；外部程序打开的新标签页可选同样处理。
- 钉住的分组不会被“删空”：最后一个标签页关闭后，用同标题、同颜色的分组重建一个未激活的空白页。
- Chrome 开启“继续浏览上次打开的网页”时，重启后分组、标题、颜色和顺序原样恢复，扩展再套用上述规则。

无构建、无依赖、无网络请求、无 host 权限。

## 安装

1. 打开 `chrome://extensions`，开启“开发者模式”。
2. “加载已解压的扩展程序”，选择本仓库根目录。
3. 可选：把扩展固定到工具栏，点击图标打开弹窗；弹窗里的“设置”进入选项页。

要求 Chrome 124 或更高版本。

## 行为规则

### 分组在前

钉住的分组按设置中的顺序排在最前，其余分组保持当前相对顺序，未分组标签页排在所有分组之后。固定标签页始终位于标签栏最左侧；Chrome 不允许分组排到固定标签页之前。

### 默认分组

每个窗口的未分组标签页会被收进一个普通 Chrome 分组，默认标题 `其他`、颜色灰色。从固定状态取消固定的标签页没有分组，也会在下一轮整理时进入默认分组（`defaultGroup` 开启时）。该分组在创建时位于标签栏最右侧；之后你可以手动拖动它，扩展不会反复纠正位置。标题和颜色可在选项页修改。

Chrome 会话恢复可能留下多个同名默认分组（典型场景：非正常退出后由外部链接拉起浏览器）。扩展启用时，归一化会检测同标题的重复分组并把所有标签页合并到一个：优先使用 remembered 分组，其次是标签页更多的分组，再次是最近使用的分组。该修复只移动已经分组的标签页，不会把未分组标签页收进默认分组，因此关掉 `defaultGroup` 规则后仍然生效。被合并清空的分组不会因为钉住保护而被重建。

### 只展开一个分组

激活某个分组的标签页时，该分组展开，其他分组折叠。点击一个折叠分组的标题时（`expandHeaderClick` 开启），扩展会激活该分组中最近使用的标签页，从而展开它并折叠其他分组。

点击一个**已经展开**的分组标题时，由 `expandedGroupHeaderClick` 选择三种行为之一，三种行为都不受固定标签页影响（`singleExpanded` 关闭时，折叠非活动分组为普通折叠，折叠当前活动分组仍执行所选行为）：

- `newtab`（新建标签页）：在点击的分组内新建一个 `chrome://newtab/` 标签页，激活它并保持分组展开。如果 Chrome 已为该次点击创建了占位页，扩展直接接管它，不再关闭后重建。
- `collapse`（折叠）：点击**非默认分组**时，收起该分组，展开默认分组并激活其最近使用的标签页；点击**默认分组**时不做任何分组变更（保持展开，激活其最近使用的标签页）。没有默认分组时按 `noaction` 处理。
- `noaction`（不处理）：无论点击默认还是非默认分组，当前分组保持展开，焦点回到该分组最近使用的标签页；其他分组保持折叠。

关于 Chrome 占位页：点击已展开分组时，Chrome 可能先新建一个空白标签页以便移动焦点。`newtab` 模式直接复用这个占位页，因此只有一次页面创建；`collapse` / `noaction` 模式先激活目标标签页，再关闭占位页，避免删除活动标签页触发额外的页面切换。识别依赖 300ms 内的创建时间与 opener 归属，`collapse` / `noaction` 下仍可能看到 Chrome 原生占位页短暂闪现。

普通地激活一个固定标签页（不是点击分组标题）时：

- `keepLastWhenPinned` 开启（默认）：上次展开的分组保持展开，保证始终有一个展开的分组。
- `keepLastWhenPinned` 关闭：所有分组折叠，新标签页进入默认分组。

`keepLastWhenPinned` 只影响“活动标签页是固定标签页”的情况。从某个分组按 Ctrl+T 时，新标签页本身暂时是未分组的活动标签页，它仍然进入刚才展开的分组，与该设置无关。

Chrome 自身不允许折叠包含当前标签页的分组，扩展遵循这一限制。

### 新标签页归属

| 来源 | 行为 |
| --- | --- |
| Ctrl+T、`+`、地址栏新建标签页 | 进入当前展开的分组（分组末尾） |
| 页面中的链接（Ctrl+点击、中键、`target=_blank`、`window.open`） | 保持 Chrome 默认行为：自动加入打开者所在分组，扩展不移动 |
| Chrome 自带的“在新标签页组中打开”“在右侧打开新标签页” | 保持 Chrome 默认行为 |
| 外部程序打开（终端、其他应用） | `externalNewTabInActiveGroup` 开启时进入展开分组，否则进入默认分组（`defaultGroup` 关闭时保持未分组） |
| 扩展自身的设置页等页面 | 不参与新标签页快路径；随后按默认分组规则处理 |

Chrome 没有“在创建前拦截 Ctrl+T”的 API，因此新标签页可能短暂显示为未分组，通常在一两百毫秒内归位。Chrome 157 会把外部程序新标签页的 `openerTabId` 设为当时的活动标签页；扩展仍按 `externalNewTabInActiveGroup` 处理，不会把它当成链接标签页。

### 钉住分组

选项页维护一个有序的钉住列表。识别依据是**分组标题 + 颜色**（标题区分大小写、精确匹配）：

- 列表顺序就是标签栏顺序；没有打开的对应分组会被跳过，选项页显示“未打开”。
- 多个窗口中的同标题同色分组会一起钉住，并按配置顺序排在一起。
- 在 Chrome 中重命名或改变颜色会让分组失去钉住状态，直到重新钉住。
- 同标题但不同颜色的分组是不同身份。例如钉住红色 `Default` 后，从已保存分组恢复的蓝色 `Default` 不会被保护，也不会进入钉住顺序。选项页的下拉列表会按颜色区分同名分组。
- 无标题分组不能钉住。

Chrome 没有禁止删除分组的 API，也没有 `tabGroups.close`。保护方式是“保证分组永不空”：

- 关闭分组内最后一个标签页、Chrome 的“关闭分组”“删除分组”：重建同标题、同颜色的分组，放入一个未激活的 `chrome://newtab/` 空白页。真实标签页不会被重新打开。
- Chrome 的“取消分组”：仍然存活的标签页会被重新归入同标题同色的分组，不会额外添加空白页。
- 把分组移动到新窗口：新窗口中保留原分组，不在旧窗口补空白分组。
- 关闭整个窗口或退出浏览器：不重建，交给 Chrome 的会话恢复。
- 空白页被关闭后，分组会再次以新的空白页出现，这是保护机制的预期行为。
- 如果被重建的分组删除前处于展开状态，重建完成后焦点会交给默认分组并展开它（没有默认分组时保持 Chrome 的选择）；其他钉住分组不会抢占展开位置，固定标签页是否存在也不影响结果。
- 取消钉住后，分组可以正常删除；非钉住分组不受保护。

### 启动恢复

扩展不保存、不恢复标签页 URL，也不做自己的会话快照。Chrome 开启“设置 → 启动时 → 继续浏览上次打开的网页”时，标签、分组、标题、颜色和顺序由 Chrome 原生恢复；扩展在浏览器启动后先保持只读，等连续 1.5 秒没有新建/移动事件（最多等 30 秒），再重新套用“分组在前 / 默认分组 / 只展开一个”的规则。

如果 Chrome 的启动设置是“打开新标签页”，扩展不会自行恢复会话。

## 设置项

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关；关闭后不做任何修改，固定分组保护也停止 |
| `groupsFirst` | `true` | 分组标签页排在未分组标签页之前 |
| `defaultGroup` | `true` | 未分组标签页收进默认分组 |
| `singleExpanded` | `true` | 同时只展开一个分组 |
| `keepLastWhenPinned` | `true` | 激活固定标签页时保留上次展开的分组 |
| `externalNewTabInActiveGroup` | `true` | 外部程序打开的新标签页进入当前展开的分组 |
| `expandHeaderClick` | `true` | 点击折叠分组标题时切换到该分组最近的标签页 |
| `expandedGroupHeaderClick` | `collapse` | 点击已展开分组标题：`newtab` 组内新建标签页；`collapse` 非默认组收起并展开默认组；`noaction` 保持当前分组 |
| `defaultGroupTitle` | `其他` | 默认分组标题，最长 30 字符 |
| `defaultGroupColor` | `grey` | 默认分组颜色，九种 Chrome 颜色之一 |
| `pinnedGroups` | `[]` | 有序的 `{title, color}` 列表；顺序即标签栏顺序 |

设置保存在 `chrome.storage.sync` 的单个 `settings` 键中。选项页的所有修改都通过后台的 `save-settings` 消息写入；修改默认分组标题/颜色时，后台会先重命名现有默认分组，再持久化设置：

- 重命名在总开关关闭时也会执行（这是对默认分组本身的直接修改），避免重新启用后旧分组残留、又新建一个默认分组。
- 默认分组已钉住时，钉住列表中的对应项会同步改成新标题/颜色，位置不变。
- 新标题不能与已打开的其他分组同名，否则那个分组会被当作重复默认分组合并；这种修改会被拒绝并在选项页提示。

弹窗提供分组数、当前分组、总开关和“立即整理”；完整设置只在选项页。

### 快捷键

- `Alt+W` 切换到最近聚焦窗口的默认分组，并激活该分组最近使用的标签页。
- 选项页“快捷键”卡片显示当前按键；点击“更改”打开 Chrome 的扩展快捷键页面。
- Chrome 不允许扩展通过 API 直接修改快捷键，因此快捷键不写入 `settings`，也没有扩展内输入框；在 Chrome 页面修改后，回到选项页会自动刷新显示。

## 隐私

- 没有网络请求，没有远程代码，没有 host 权限。
- `tabs` 权限只用于在新标签页创建后的短暂窗口内读取 `url` / `pendingUrl`，以区分 `chrome://newtab` 与外部 URL；URL 不写入存储、不打印日志、不发送。
- `chrome.storage.session` 中的固定分组快照只包含分组 ID、窗口 ID、标题、颜色、折叠状态和标签页 ID。
- 设置中不包含任何 URL 或浏览历史。

## 已知限制

- Chrome 不允许扩展绘制或钉住分组标签，也不能把分组排到固定标签页之前。
- 无法真正禁止删除分组；只能通过“保持非空”重建。Chrome 的“已保存的标签组”界面里可能同时出现重建后的分组和旧的保存项。
- 无法读取或修改 Chrome 的“启动时”设置。
- 默认分组是普通分组：关闭它会关闭其中的标签页；关闭 `defaultGroup` 规则才能保留手动取消分组的结果。
- 在 Chrome 中手动重命名默认分组后，扩展不会跟随：该分组变成普通分组，之后的未分组标签页会进入新建的默认分组。
- `collapse` / `noaction` 下点击已展开分组的标题时，Chrome 会先自行选择焦点：有固定标签页时激活它，否则创建占位页，然后才通知扩展。扩展无法拦截这段原生行为，可能看到一次短暂切换或空白页闪烁；`newtab` 只会复用或创建一个组内 NTP。
- 占位页识别依赖 Chrome 设置 `openerTabId` 且创建时间在 300ms 内；其他 Chrome 版本若改变该行为，可能多出一个占位标签页，或让扩展无法复用占位页而另行新建。
- 快捷键由 Chrome 管理；扩展只能读取和展示，不能通过 API 直接改写。快捷键冲突或被清空时，选项页显示“未设置”。
- 固定分组保护只在扩展就绪后生效；浏览器启动的最初约 1.5 秒内删除的分组不会被恢复。
- 启动恢复依赖 Chrome 自己的会话恢复；扩展不保存 URL，也不提供跨浏览器配置同步之外的备份。

## 开发

```bash
npm test
```

测试使用 Node 内置的 `node:test`，无第三方依赖。注意：`package.json` 中的脚本是 `node --test test/*.test.js`；Node 24 不接受把 `test/` 目录直接作为参数。

变更记录见 [CHANGELOG.md](CHANGELOG.md)。

目录：

```
_locales/              多语言本地化资源（en, zh_CN, zh_TW）
manifest.json          MV3 清单（tabs / tabGroups / storage）
icons/                 扩展图标（SVG 源文件 + 16/32/48/128 PNG）
src/background.js      服务 worker：事件接线、窗口归一化、固定分组保护
src/i18n.js            UI 本地化辅助模块
src/lib/layout.js      纯函数：排序、折叠、新标签页目标
src/lib/pinned.js      纯函数：钉住标题+颜色匹配与恢复方式
src/lib/settings.js    设置默认值、校验、读写
src/options.*          选项页
src/popup.*            工具栏弹窗
test/*.test.js         纯逻辑单元测试 + 后台事件接线测试（fake chrome）
test/fake-chrome.js    后台测试共享的 fake chrome API
```

### 发布

版本号以 `manifest.json` 为准，并与 `CHANGELOG.md` 同步更新。发布使用 `v<version>` 标签：

```bash
git tag v0.4.0
git push origin v0.4.0
```

`.github/workflows/release.yml` 会运行 `npm test`、校验标签与清单版本、打包 `tabgroup-manager-<version>.zip`（含 `manifest.json`、`src/`、`icons/`、README、CHANGELOG），并创建或更新 GitHub Release 资源。

手动验收：加载已解压扩展后，至少检查默认分组、分组排序、单展开、Ctrl+T 归属、钉住分组删空重建、取消钉住后可删除，以及开启“继续浏览上次打开的网页”后的重启恢复。

面向维护者和编码代理的架构说明、状态机与踩坑记录见 [agent.md](agent.md)。
